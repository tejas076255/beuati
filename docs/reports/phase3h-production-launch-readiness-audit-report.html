P1 — Must Complete Before Deployment

IDFinding
P1-1Production env vars must be set on the real host. Live-tested by running the actual built Cloudflare Worker (.output/server/index.mjs) via wrangler dev: without SUPABASE_URL/SUPABASE_PUBLISHABLE_KEY/VITE_SITE_URL injected, every portfolio/service page and the dynamic sitemap return 500. This is expected — .env is local/Vite-only and never transfers to the deployed Worker automatically. Not a bug: the app fails safely with a clean generic error page (see below), and Lovable's own error text ("Connect Supabase in Lovable Cloud") anticipates this exact step.
P1-2Migration tracking gap. 18 migration files exist in the repo; only 1 is recorded in supabase_migrations.schema_migrations live. The live schema content is verified correct (matches all 18 files' cumulative effect, extensively tested throughout 3G) — this is untracked, not drifted. But standard Supabase CLI tooling (db push) could conflict with this state if used carelessly in the future.

P2 — Should Fix Soon (not launch blockers)

  • .env is tracked in git (not in .gitignore) — no actual secret exposed today (only the public/anon key + project ID + site URL, all safe-by-design to be public), but a best-practice gap for the future.
  • No custom security headers configured (only asset caching in the generated _headers file) — not urgent since RLS + auth middleware are the real security boundary.
  • The build's own printed hint ("preview with npx vite preview") doesn't work for this project's Cloudflare/Nitro output — confirmed live; real local verification needs wrangler dev.
  • 3 already-known 3G CRM P2 items (filter enquiry-awareness, snapshot labels) — reconfirmed, still not blockers.
  • Cosmetic: trailing whitespace in the live "Bridal Makeup Artist " title field.

Deployment Architecture (Verified)

TanStack Start via @lovable.dev/vite-tanstack-config, which wires Nitro with Cloudflare as its default build target — confirmed via the config file's own comment and the generated wrangler.json. npm run build produces a real Cloudflare Worker script, not a static export. /sitemap.xml is a genuinely dynamic, database-driven, server-executed route (custom fetch intercept in src/server.ts).

Recommended host: Lovable's own native publish path — the entire toolchain is purpose-built for it, and the app's own error messages anticipate it. Static-only hosting (plain Hostinger, static export) would break the app — confirmed the dynamic sitemap and every SSR route require a live server runtime. Vercel is technically possible but would need a Nitro preset change (out of scope for a read-only audit) and is unverified.
