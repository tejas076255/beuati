1–5. Audit & Architecture

Grepped the entire repo for gtag/dataLayer/GTM/GA4/Meta Pixel before writing anything — none existed, confirming a genuinely new foundation. Chose window.dataLayer — the standard interface both GTM and GA4/gtag.js already consume, and that Meta's CAPI tooling can be pointed at later via a GTM trigger. No SDK installed, no script loaded unless a real VITE_GTM_ID is configured — currently unset, so the app ships with zero analytics network calls today.

8–17. Configuration, Privacy & Dedup Discipline

Env convention: VITE_GTM_ID, following the exact pattern of src/lib/site-url.ts — trimmed, empty-string fallback, never hardcoded.
No-PII rule: availability_form_success carries only profile_slug, page_path, service_id, service_name, event_date_present (boolean), lead_source — never name/phone/message/location text. No call site anywhere passes free-text customer input to trackEvent.
Dedup: useTrackedPageView fires at most once per key via a useRef guard — survives SSR, hydration, and React Strict Mode's dev double-invoke, while still firing again on genuine navigation to a different profile/service. Form-start uses a single onChangeCapture handler on the <form> element, not one per field.
WhatsApp honesty: event is named whatsapp_click, never whatsapp_message_sent — no delivery claim.
CTA-location vocabulary: one shared typed set (hero, hero_card, service_card, package_card, availability_section, final_cta, mobile_sticky, floating_whatsapp, service_detail_header, service_detail_hero) — never free text.

18–20. Lead-Source, UTM & Referrer Audit

Lead-source architecture: leads.source (channel-level) plus the beautician_profile_id FK already answers "which professional." There is no persisted per-inquiry CTA-location or service-page attribution in the CRM — the new analytics events answer that, but only in the analytics layer, deliberately not the CRM (zero-schema-change scope for this phase).

UTM audit: confirmed zero UTM capture anywhere in the repo (grep for utm_source/utm_campaign/URLSearchParams — no matches). No migration applied. Persistent CRM-level UTM attribution would need a new column — flagged as future work per the phase's own STOP-and-report instruction, not implemented now.

Referrer audit: confirmed zero document.referrer capture. Feasible as a non-invasive analytics-only property later; out of this phase's minimum-foundation scope.

21–23. Future-Readiness & Debug Safety

No Google Ads/Meta conversion or pixel IDs invented anywhere — everything routes through dataLayer so a real GTM container can wire these up later with zero app code changes. No internal lead UUID is ever passed to trackEvent. Debug output is console.debug, gated on import.meta.env.DEV only — never production, never a dashboard.
