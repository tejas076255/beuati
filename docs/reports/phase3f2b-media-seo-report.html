5–7. Gallery, Before & After, Video Implementation

Dashboard copy is user-friendly, never mentions "SEO" or "alt attribute": "Photo description" with helper text "Describe what is visible in the photo. This helps accessibility and search engines understand your work." Clearing a field back to empty writes null and hands control back to the automatic fallback. Videos have no manual field (no schema support) — thumbnail alt is always generated from real title/category, e.g. "My bridal work — video by Dharti R Panchal."

8. Alt-Text Fallback Hierarchy

  1. Manual text (alt_text / caption) — used verbatim, no boilerplate appended
  2. Title + category
  3. Title + professional/service context
  4. Category + owner name + city
  5. Safe generic fallback — never the literal "image"
Before/after pairs are guaranteed non-identical: the "before" side never carries the professional's name; the "after" side always attributes the result to them.

9. Image Performance

No new CDN, no Storage rebuild, no transformation pipeline (out of scope). Existing lazy-loading and fixed width/height CLS-prevention attributes confirmed intact — this phase only changed alt values, never markup, sizing, or loading strategy.

10. Structured Data — Live Verified

Fetched the raw SSR response for /portfolio/dharti-panchal directly (not via client hydration) and parsed the JSON-LD script block:
  • 5 ImageObject entries — real Storage contentUrl, real caption/description, real creator, real dateCreated where available
  • 3 VideoObject entries — real thumbnailUrl/name/description, real embedUrl (Instagram/YouTube) or contentUrl (uploaded), real uploadDate
  • No fabricated durations, dates, creators, or thumbnails anywhere — a property is simply omitted when the underlying data doesn't exist (e.g. no duration key when duration_seconds is null)

11. RLS / Ownership Verification

updateImageAltText() uses a direct .update(...).eq("id", imageId) with no explicit ownership join in application code — consistent with this codebase's established pattern of trusting RLS rather than re-implementing ownership checks client-side. Both image tables' owner-write policies use the shared owns_beautician_profile() helper (confirmed in the Phase 2 data-model audit), so a cross-user write is rejected by Postgres before it can apply. Public reads remain scoped to is_published: true rows only, unchanged.
