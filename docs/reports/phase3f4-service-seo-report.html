1. Existing Service Architecture Discovered

services.slug already existed but was never written to (always NULL, no constraint). Two genuine but unpopulated FK relationships found: portfolio_items.service_id and before_after_items.service_id → services.id, plus an unused package_services junction table. services.category and portfolio_items.category use incompatible vocabularies — confirming no safe category-based media relationship exists.

Conclusion: a stable SEO URL required a schema change — documented here before implementing, per instruction.

2–3. URL Architecture & Slug Strategy

/portfolio/{profileSlug}/services/{serviceSlug}, exactly as specified. Primary city never baked into the URL. Migration adds a format CHECK + per-profile unique index. createService() generates a real slug with a retry-on-conflict loop (same pattern as profile-slug generation); updateService() never regenerates an existing slug. A computed fallback (slug ?? slugify(name)) makes every existing service work today, self-healing into a persisted slug on next dashboard save.

Action needed from you: I could not apply supabase/migrations/20260823180000_service_slugs.sql to your live database myself — this environment has no Supabase access token. Please apply it via the CLI or dashboard SQL editor. Everything still works correctly without it (via the computed fallback), just without the database-level uniqueness guarantee.

4–5. Database & Files Changed

One additive migration (touches no existing data). New: service-page-query.server.ts, the service-page route, the migration file. Modified: seo-helpers.ts, services.server.ts, the portfolio mapper/type, server.ts (sitemap), portfolio-sections.tsx (internal links), seo.server.ts + dashboard.seo.tsx (Service Search Pages list), dashboard.services.tsx (one-line helper text).

6. Indexability Eligibility Rule

Deterministic, no arbitrary score — noindex unless all of: portfolio indexing is on, primary city is set, and the service description is at least 40 characters. The exact same function is shared by the page's own robots directive, the sitemap generator, and the dashboard list, so they can never disagree.

Live-verified on the real test profile: "HD Bridal Makeup" (real description) → index, follow, appears in sitemap. "Nail Art" (no description) → noindex, follow, page still renders normally, correctly excluded from sitemap.
