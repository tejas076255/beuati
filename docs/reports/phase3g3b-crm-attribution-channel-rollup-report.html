1–4. UX Placement & Metric Definitions

Extended the existing List / Cards / Pipeline view switcher on /dashboard/leads with a 4th mode, Insights — no new route, matching the CRM's own navigation pattern. When active, the Today command center and per-lead filters hide, since Insights is an aggregate rollup, not a per-lead worklist.

Total enquiries = count of lead_inquiries rows in range. Unique customers = distinct lead_id. UTM-attributed = utm_source present. Unattributed/historical = source, utm_source, referrer_host, AND cta_location all NULL — never relabeled "Direct." Coverage is reported as three separate honest percentages (Source / UTM / CTA recorded) rather than one collapsed score, since source alone trends toward 100% and would be misleading on its own.

5–19. Design Decisions

Date filter: 7d/30d/90d/all, default 30d, strictly on lead_inquiries.created_at (never event_date). Live-verified genuinely different counts: 7d=13, 30d=15, 90d=15, all=15.
UTM channel / campaign: raw recorded utm_source/utm_medium/utm_campaign values only — no invented groupings, no revenue/ROAS/CPA/conversion-rate columns (explicitly excluded, §9).
Landing/conversion pages: pathname-only top-10 lists; conversion pages kept as a secondary section.
Referrer: conditionally rendered — currently absent, since zero non-null referrer_host values exist yet; will appear automatically once real data arrives.
Explicitly NOT built: conversion rate (no session/traffic denominator exists), pipeline-performance-by-channel (status is customer-level, attribution is enquiry-level — combining them risks misleading conclusions), revenue/LTV (no billing data exists yet).

20–25. Architecture, Security & Privacy

Database changes: zero. Single query per rollup — lead_inquiries joined to leads!inner(beautician_profile_id) (explicit scoping, defense in depth beyond RLS) and lead_inquiry_services(service_tag) inline, avoiding N+1. All grouping happens server-side in lead-insights.server.ts — only aggregated counts cross to the browser.
Privacy: the select() never touches name/phone/email/message/notes — confirmed by code review, only channel/campaign/service/path fields are fetched or rendered anywhere in the Insights view.
Security: ownership resolved via getOwnBeauticianProfileId() and applied as an explicit filter on top of unchanged RLS policies — never assumes a single global profile.

26–27. Responsive Design

Reused the existing StatCard visual language — no new charting library installed. Breakdown sections use a 2-column grid on desktop collapsing to 1 column on mobile; bars are plain CSS width divs; all lists stack vertically with no horizontal overflow.
