1–2. Audit & Required/Recommended Model

Found three separate, potentially-disagreeing readiness concepts before this phase: the Phase 3F.1 18-check scored system, the main portfolio route's robots directive (toggle-only, no content gating), and a third informal completeness percentage on /dashboard/profile. All three are now one system.

A. Save validity
Can the professional save the profile? Unchanged zod schema.
B. Publication
Is the portfolio published to visitors? profile.status === "published".
C. Search readiness
Is it strong enough for index, follow + sitemap? One shared function.
States
Ready for search / Needs improvement / Not indexed — never a percentage.

6–8. Dashboard UX, Live Draft & SEO Page

The old percentage bar on /dashboard/profile is replaced by a compact "Portfolio readiness" panel — state badge, message, Required/Recommended mini-checklists. form.watch() (already used for the existing live-preview identity card) now also drives readiness on every keystroke, combined with a separately-loaded static context for signals this page doesn't itself edit (services, gallery, reviews). An "unsaved changes" banner appears when the draft differs from the saved row. /dashboard/seo's old ScorePill is gone, replaced by the deterministic state plus a grouped Required / Recommended / Technical SEO checklist with inline deep links.

9–11. Primary City, Profile Image & About Quality

Profile image was audited and promoted to REQUIRED (a missing photo weakens trust, the OG fallback, and Person entity completeness — genuinely different from services, which never had an image concept). Verified safe against real data. Primary city stays required and was live-tested (see §17). Bio reuses the exact MIN_BIO_LENGTH = 80 threshold from the retired system — never a new number, and the helper text never mentions a character count to the user.

12–16. Services, Work, Reviews, Availability & Categorization

  • The portfolio helper consumes only activeServiceCount — it never recomputes individual service readiness, which stays owned by Phase 3F.8's model
  • Gallery/Before-After counts are recommended-only, sourced from real is_published rows — never client_count
  • Reviews stay recommended-only and deliberately have no deep-link nudge on the SEO dashboard
  • Availability/service areas are recommended-only; primary city remains the sole required local-search signal
  • Every check carries an explicit category (content/local/trust/technical) and required flag, so content issues are never visually mixed with technical hygiene

17–18. Indexability & Sitemap Consistency — Live-Verified

Cleared Dharti's primary_city → public robots meta flipped to noindex, follow and the profile disappeared from /sitemap.xml. Restored it → back to index, follow, sitemap-included again. The robots meta is now always explicit (previously sometimes omitted entirely), computed from the identical indexable boolean the sitemap query derives independently — zero drift observed.

19–20. Query Safety & Performance

The new Profile-page readiness query uses a dedicated cache key (own-portfolio-readiness-context) — never reusing own-services or any other route's key, directly applying the Phase 3F.8A.1 lesson. No N+1: the sitemap query uses one batched .in() call for active-service counts across all profiles; both dashboard pages run a fixed small number of batched queries regardless of data volume.
