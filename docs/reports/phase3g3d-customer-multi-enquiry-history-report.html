1–2. Audit & Field Classification

Found the exact bug this phase targets: the old "Customer & inquiry summary" grid mixed customer-level fields (email, leads.source, leads.created_at labeled "Received") with latest-enquiry-only fields (event date/type/persons/location/venue/services) as if they were one coherent record. The Attribution block also only ever read the single latest inquiry. Confirmed live: lead_activities has no inquiry_id column — activities correctly remain customer-level only, not per-enquiry.

3. Query Architecture — Zero New Queries

LeadWithInquiry extended with inquiries: LeadInquiry[] (newest first) alongside the existing inquiry field. The underlying query already fetched every inquiry via the join — the mapping function simply stopped discarding everything past index 0. No new server function, no N+1, fully backward-compatible with every existing List/Cards/Pipeline/Add-dialog consumer.

4–11. Workspace Redesign

Customer header: added "N enquiries · email" — genuinely customer-level facts only; leads.source removed entirely from the summary (previously shown as a fake permanent attribute).
Enquiries section: new accordion — newest first, "Latest enquiry" badge on the newest, collapsed by default except the latest to avoid excessive length. Each card independently shows its own service(s), event details, source, and attribution — using lead_inquiry_services and lead_inquiries, never the stale leads.service_requested/leads.source snapshot.
Source labeling: a dedicated enquirySourceLabel() treats NULL as "Unknown / historical" — never "Manual Entry", never "Direct" — matching the exact semantic already established in Insights (3G.3B/3G.3C).
Attribution: renders per-card only when that specific enquiry has real values — never merged across enquiries.

12–17. CRM Sections Preserved Unchanged

Pipeline status, follow-up (next_followup_at/reason, last_contacted_at), activity timeline, and internal notes are all completely untouched — still one customer-level value each, visually separate from the new Enquiries section. The existing "Matched via Insights" banner from 3G.3C is preserved; per-card "Matches insight" tagging was deliberately not added, since the drill-down API returns which customer matched, not which specific inquiry id(s) — a fragile heuristic was avoided per the phase's own "if excessive complexity, retain the existing banner only" instruction.

18–21. Empty State, Mobile, Accessibility, Security

Empty state ("No enquiry history recorded.") guards against a zero-inquiry customer. Cards are full-width stacked blocks — no tables, no horizontal scroll risk. Accordion headers are real <button> elements with aria-expanded/aria-controls — keyboard operable. No new query surface was introduced, so security/RLS posture is unchanged from before this phase.
