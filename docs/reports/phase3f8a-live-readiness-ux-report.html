3. Draft/Live Readiness Architecture

No second algorithm was written. The Add/Edit dialog calls the exact same evaluateServiceContentReadiness() the server uses, fed form.watch() values, the local included/suitable-for arrays, and the visibility toggle in place of the persisted row — combined with a readinessContext (profile published, indexing enabled, primary city, review count, service-area count) loaded once per page visit, plus a per-service linkedWorkCount from the same batched query.

4. Unsaved-State Behavior

A hasUnsavedChanges flag (dirty form, or the visibility/list state differs from the persisted row) drives an amber "Preview based on unsaved changes — save to apply these to your public service page" banner, and the summary message becomes "Will be ready for search once you save" instead of implying the page is already live. Closing without saving and reopening correctly restores the persisted checklist.

5–6. Actionable Guidance

  • "Portfolio work linked" (when missing) now shows inline "Gallery" / "Before & After" links
  • Missing city → "Add in Profile" (/dashboard/profile)
  • Missing service areas → "Add service areas" (/dashboard/areas)
  • Reviews deliberately has no action — stays optional guidance only, never a nudge implying reviews are required

No media/relationship UI was added inside the dialog — Phase 3F.5's service_id relationships remain the only way to actually link work.

7. Price-Validation UX

Wording changed to "Enter a price greater than ₹0, or choose Custom quote" (fixed/starting_from) and "…or leave blank for Custom quote" (custom_quote with an invalid non-blank entry) — pointing at the app's actual price-type option. Validation strictness is unchanged: fixed/starting_from still require a positive price, custom_quote still allows blank, ₹0 is never displayable, and Phase 3F.3's structured-data pricing logic was not touched.

8–9. Saved-State Synchronization & Sitemap/Robots Consistency

Confirmed by construction: the service card list and /dashboard/seo read only from server-computed data, never from dialog-local state — the live preview exists solely inside the open dialog instance. Live-verified: hd-bridal-makeup and nail-art (both already improved to meaningful descriptions) resolve index, follow and remain sitemap-included — nothing about this correction altered the saved-data indexability chain.
