5–6. Shared Readiness Logic & Description Quality

One function, evaluateServiceContentReadiness(), used identically by /dashboard/services, /dashboard/seo, and (via the unchanged evaluateServiceIndexability() it wraps) the public route's robots directive and the sitemap. Live-verified: real "HD Bridal Makeup" stayed index, follow and sitemap-included after the slug-persistence check was added.

The existing 40-character description threshold was preserved exactly (internal only, never shown as a number to the user). Verified against real production data: Nail Art (0 chars) and Sider makeup (1 char) correctly fail; Airbrush/Party & Sangeet/HD Bridal (65–75 chars) correctly pass.

7–8. List/Preparation Validation & Silent-Default Audit

Added a 12-item cap for What's Included / Suitable For and a 1000-character cap for preparation notes — enforced identically client-side (disabled "+ Add item" past 12) and server-side (throws). Confirmed real user-entered content ("Hd make up", "Pls wash you hair before 4 hours for dry") is preserved verbatim — no rewriting, no grammar correction. Price/duration silent-default protections from Phase 3F.6 remain untouched.

9–11. Dashboard UX — Cards, Edit Dialog, SEO Page

  • Service cards: compact readiness badge ("Ready for search" / "Needs details" / "Not indexed"), "Hidden" badge when inactive, up to 2 top reasons when not ready
  • Edit dialog: new "Service page readiness" panel — Required and Recommended checklists visually separated, "Ready" or "Needs N required improvements" summary, Profile deep-link when city is missing
  • SEO dashboard: "Service Search Pages" now lists every service including unpublished ones, using the same 3-state label

12–13. Public/Indexability Behavior & Sitemap Consistency

Live-verified end-to-end: toggling Nail Art's is_active off removed it from /sitemap.xml and its direct URL returned 404 immediately; toggling back on restored both (200, sitemap entry present) — confirming dashboard, robots, and sitemap can never disagree.

14–17. Regression, Profile Guidance, RLS, Performance

Price/duration: server-side validateServiceContent now mirrors the client rules exactly, closing a real gap where only the browser enforced them. Performance: confirmed no N+1 — 6 fixed batched queries per /dashboard/services load regardless of service count.
